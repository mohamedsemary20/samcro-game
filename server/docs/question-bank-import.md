# Question bank import and eligibility

The canonical source is `web/questions/trivia_clean.json`. `npm run questions:validate` recursively reads the configured source directory, preserves stable IDs and original question text, and normalizes supported non-negative safe-integer answers. The original type, unit, topic, confidence, source hint, file, collection, index, and fingerprint remain recorded in database metadata. Decimal answers that the current BigInt scoring model cannot represent, malformed records, unsupported types, and conflicting IDs are excluded without rounding or merging.

## Eligibility

`Question.enabled` is the single gameplay eligibility flag. A question can be imported and activated when structural validation succeeds. The old `ApprovedQuestionHint` table and editorial review JSON are retained as legacy data, but their approval fields no longer gate question import or play and imports do not overwrite or delete them.

Gameplay hints are generated by the server from the numeric answer for each player when requested. The selected range always contains the answer, the exact-answer tier remains private, and public question state never contains the answer or private hint. The import pipeline does not copy `source_hint` into player-facing text and does not fabricate factual citations or review notes.

## Commands

```powershell
Set-Location server
npm.cmd run questions:validate
npm.cmd run questions:import
```

The build also compiles the importer for production hosts that omit development dependencies. After `npm run build`, run `npm run questions:validate:built` and `npm run questions:import:built`; these use the host-provided `DATABASE_URL` and load `.env` only when the file exists.

`questions:import` is idempotent. It updates only records owned by the same source file, refuses a stable ID owned by a different source, preserves legacy hint rows, activates eligible records, and deactivates source-owned records that are no longer structurally eligible. All writes run in one serializable transaction. Run it with `DATABASE_URL` pointing to the intended database; the command never chooses or substitutes a database.

The game start transaction selects five distinct enabled questions from PostgreSQL with supported types and non-negative safe-integer answers. It refuses to start when fewer than five eligible questions remain. Test question pools remain development/test-only and are not part of the production importer or selector.

## Migration

Migration `20261027000000_structural_question_eligibility` safely activates legacy rows from the canonical source only when their prompt, category, type, and numeric answer are structurally valid. It leaves question text, answers, source metadata, and all legacy hint/review rows unchanged. It adds an index for active question selection. Apply through `npm run db:deploy` only after verifying the target database identity.

The validator writes normalized JSON and machine/human-readable audit reports under `server/data` and `server/reports`. These generated files are diagnostics, not gameplay approval records. `server/data/question-bank-hints.review.json` is kept as a historical review artifact and is not rewritten by validation or import.
